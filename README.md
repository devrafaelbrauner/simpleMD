# simpleMD

Editor de markdown open source (MIT), extensível por plugins e temas, em que o **markdown fica visível** (modelo Obsidian / VSCodium), com renderização inline. Os arquivos são `.md` puros em uma pasta do usuário ("vault").

O plano completo está em [`PLANO.md`](PLANO.md). O andamento por etapa está em [`TAREFAS_PENDENTES.md`](TAREFAS_PENDENTES.md), as mudanças em [`CHANGELOG.md`](CHANGELOG.md) e as ideias para depois em [`MELHORIAS.md`](MELHORIAS.md).

## Instalar (pré-lançamento sem assinatura)

A única fonte oficial dos instaladores é a página de releases: <https://github.com/devrafaelbrauner/simpleMD/releases>. Não baixe o simpleMD de outro lugar. A versão 0.1.2 é um **pré-lançamento sem assinatura de código**: nem a Apple nem a Microsoft conferiram quem publicou os arquivos, então o macOS e o Windows avisam que não conseguem verificar o desenvolvedor. A versão do macOS continua sem assinatura de código por decisão (sem Developer ID da Apple); a assinatura do Windows está em estudo.

- **Plataformas:** macOS em Apple Silicon (M1 ou mais novo; Macs Intel não são suportados nesta versão), arquivo `simpleMD_<versão>_aarch64.dmg`; Windows x64, arquivo `simpleMD_<versão>_x64-setup.exe` (instala em `%LOCALAPPDATA%\simpleMD`, só para o seu usuário, sem administrador). A instalação real foi testada com a versão 0.1.0, no macOS 27.2 (Apple Silicon) e no Windows 10 IoT Enterprise LTSC 21H2 (x64); na 0.1.1 o app foi aberto no macOS 27.2; a 0.1.2 foi construída localmente a partir do `2565150` e aberta no macOS (assinatura ad-hoc), mas ainda não foi instalada a partir dos arquivos baixados em nenhum dos dois sistemas. Windows 11 não foi testado. Não há atualização automática.
- **Antes de abrir, confira o arquivo.** Baixe também o `SHA256SUMS` do release para a mesma pasta. No macOS, `shasum -a 256 -c --ignore-missing SHA256SUMS` (na pasta dos arquivos) tem de imprimir `<arquivo>: OK`; no Windows (PowerShell, na pasta dos arquivos), `(Get-FileHash .\<arquivo> -Algorithm SHA256).Hash -eq ((Select-String -SimpleMatch '<arquivo>' .\SHA256SUMS).Line -split '\s+')[0]` tem de imprimir `True`. Qualquer outra saída quer dizer que o arquivo não confere. Com o GitHub CLI autenticado (`gh auth login`) dá para conferir também a atestação de proveniência (que o arquivo saiu do workflow de release deste repositório, na tag do release), com o `.dmg` ou o `-setup.exe` no lugar de `<arquivo>` (o `SHA256SUMS` não tem atestação própria): `gh attestation verify <arquivo> --repo devrafaelbrauner/simpleMD --signer-workflow devrafaelbrauner/simpleMD/.github/workflows/release.yml --source-ref refs/tags/<tag> --deny-self-hosted-runners`, que num terminal tem de mostrar `✓ Verification succeeded!`. A soma e a atestação provam de onde o arquivo veio, não que o código está livre de defeitos.
- **Se a soma não bater, se a atestação falhar ou se o sistema disser que o app está "danificado": não abra, apague o arquivo e avise de forma privada (veja [`SECURITY.md`](SECURITY.md)).** Não tente contornar.
- **Só depois de conferir, e só para esse arquivo:** as notas do release descrevem a primeira abertura. No macOS, o aviso "O Item simpleMD Não Foi Aberto" tem o botão destacado "Mover para o Lixo": clique em "OK" e depois, em Ajustes do Sistema → "Privacidade e Segurança", seção "Segurança" ("O app simpleMD foi bloqueado para proteger o Mac."), em "Abrir Mesmo Assim". Se aparecer um segundo aviso, "Abrir o Item simpleMD?", clique em "Abrir Mesmo Assim" (não no botão destacado "Mover para o Lixo"). Clique em "Abrir Mesmo Assim" uma vez só em cada aviso e confirme com a senha ou o Touch ID sem trocar de janela. Se o pedido de senha/Touch ID não aparecer e o simpleMD não abrir: force o encerramento do simpleMD (⌥⌘Esc, escolha o simpleMD e clique em "Forçar Encerrar") e reinicie o Mac, o que deve resolver; depois repita "Abrir Mesmo Assim" uma vez só em cada aviso. No primeiro ⌘P, o macOS pergunta "Permitir que “simpleMD” busque dispositivos em redes locais?": o simpleMD só precisa disso para imprimir numa impressora de rede; se você não usa uma, clique em "Não Permitir". No Windows, o SmartScreen ("O Windows protegeu o computador") mostra, depois de "Mais informações", "Fornecedor: Fornecedor desconhecido" e o botão "Executar assim mesmo". O aviso do sistema existe para proteger você de apps de origem desconhecida: não desligue nenhuma proteção do sistema; o simpleMD não precisa disso. Se o Controle Inteligente de Aplicativos do Windows bloquear o instalador, aguarde a versão assinada.
- **Chaves de IA:** no macOS, cada nova versão sem assinatura pede uma vez acesso às chaves já salvas no Keychain; permita só logo depois de instalar uma versão que você conferiu e acabou de usar a IA, e negue em qualquer outro momento. No Windows, as chaves ficam no Gerenciador de Credenciais da sua conta, legíveis por qualquer programa que você execute. Desinstalar não apaga as chaves: use "Remover chave" em Configurações → IA antes.

## Regras de arquitetura

1. **Markdown no disco é a fonte da verdade.** Nenhum motor, cache ou índice pode alterar um `.md` sem ação do usuário.
2. **`packages/core` não conhece Tauri nem React.** Só JavaScript/TypeScript puro + CodeMirror/Milkdown.
3. **A API de plugins não expõe React nem Tauri.** `registerPanel` recebe um `HTMLElement`; acesso a arquivos passa por `api.vault`.
4. **Feature nova nasce no modo fonte.** O modo WYSIWYG recebe depois, ou nunca, se não fizer sentido.
5. **`<CodeMirrorEditor>` cria o `EditorView` uma única vez: um por grupo do editor, criado uma vez.** Comunicação por `dispatch`, não por props.
6. **Nunca sobrescrever silenciosamente** um arquivo cujo `mtime` mudou fora do app: detectar e oferecer "manter ambos".
7. **Chaves e tokens só no keychain do SO.** Nunca em arquivo de configuração.

As fronteiras entre pacotes (regras 2 e 3) são verificadas pelo ESLint (`no-restricted-imports` em `eslint.config.js`): um import proibido faz `pnpm lint` falhar.

## Estrutura

```
apps/
  demo/          página Vite de demonstração do editor (etapa 1)
  desktop/       app Tauri 2 (src/), harness de testes no Chromium (harness/) e casca Rust (src-tauri/)
packages/
  ai/            cliente de IA (provedores, chat e comandos) sobre o transporte em Rust
  core/          editor CodeMirror 6 + lang-markdown (GFM), comandos, atalhos, live preview, links,
                 wikilinks, tabelas, tarefas, sanitizador de HTML e exportação; sem React/Tauri
  plugin-api/    API v1 de plugins (congelada), runtime dos plugins e interfaces privadas dos
                 plugins internos (internal/*, fora da API v1)
  plugins-internal/  plugins internos: Mermaid, KaTeX, Cálculo, Tarefas e consultas, Vim, Lint,
                 Snippets LaTeX, Outliner, Ortografia offline e LanguageTool
  themes/        tokens CSS (tokens.css), temas embutidos, validador de theme.json, preferências
                 do vault (.simplemd/config.json), fontes mono embutidas (woff2 + OFL)
  ui/            componentes React compartilhados, como <CodeMirrorEditor>
  vault/         VaultProvider + LocalFsProvider sobre uma porta de arquivos injetável (Tauri,
                 Node nos testes, memória no harness); guarda de caminhos, conflitos, EOL/BOM,
                 catálogo e índice (.simplemd/index.json)
scripts/         portões do CI: check-tauri-security, check-ci-supply-chain, check-licenses,
                 check-single-version, assert-no-harness, assert-no-ai-recorder; deps-fix
```

Os pacotes internos são consumidos como código-fonte TypeScript (sem etapa de build por pacote).

## Desenvolvimento

Requisitos: Node.js 22 (a versão do CI está em `.node-version`), pnpm 12 (a versão exata está em `packageManager` no `package.json`) e, para o app desktop, Rust com os pré-requisitos do Tauri 2 (Xcode CLT no macOS; WebView2 e MSVC no Windows). A versão do Rust é fixada em `rust-toolchain.toml` e o rustup a instala sozinho. O `pnpm-workspace.yaml` liga a política de cadeia de suprimentos do pnpm (versões com menos de 1 dia, rebaixamento de confiança e dependências transitivas fora do registro são recusados, inclusive no `--frozen-lockfile`).

```sh
pnpm install          # instala as dependências do monorepo
pnpm lint             # ESLint + prettier --check + licenças (check-licenses) + uma cópia de cada @codemirror/*, katex e React
pnpm typecheck        # tsc --noEmit em cada pacote
pnpm test             # Vitest em todos os pacotes
pnpm test:coverage    # Vitest com cobertura (relatório em build/coverage)
pnpm format           # prettier --write
pnpm check:security   # portão estático do Tauri: capabilities sem escopo fixo, sem shell/process, CSP
pnpm deps:fix         # no branch de um PR npm do Dependabot (veja "PRs do Dependabot")
pnpm dev              # app desktop (tauri dev; o mesmo que pnpm dev:desktop)
pnpm dev:harness      # a mesma interface no navegador, com vault em memória (http://localhost:5174)
pnpm dev:demo         # demo do editor em http://localhost:5173
pnpm tauri build --no-bundle   # binário de release em apps/desktop/src-tauri/target/release/
```

### App desktop

`pnpm dev` abre a janela do simpleMD. "Abrir pasta…" (`Mod-O`) mostra o diálogo nativo; o app só recebe acesso à pasta escolhida (e à `.simplemd/` dentro dela) durante a sessão. Arquivos `.md` aparecem no explorador; clique ou Enter abre uma aba. "Nova nota…" (`Mod-N`; também na barra, na paleta e no explorador de uma pasta sem notas `.md`) cria uma nota `.md` vazia na pasta escolhida no diálogo (por padrão, a do item focado no explorador) e a abre numa aba; um nome já usado nunca é sobrescrito: o diálogo avisa e nada é gravado. As alterações são salvas 1 s depois da última tecla, e também ao fechar a aba (`Mod-W`) ou a janela. Se o arquivo mudar fora do app com alterações pendentes, o diálogo de conflito oferece "Manter ambos" (as suas alterações vão para `<nome> (conflito AAAA-MM-DD HH-mm-ss).md`) ou "Recarregar do disco"; nada é sobrescrito sem você ver. No terminal, o app imprime `simplemd:ready <ms>` no primeiro quadro e `simplemd:conflict-shown <ms>` quando o diálogo de conflito aparece.

### Android (APK)

O app roda no Android (arm64) como APK debug, gerado pelo `tauri android`. Pré-requisitos: JDK 17, Android SDK com as build-tools e a plataforma 37 (a que o projeto Gradle gerado usa em `compileSdk` e `targetSdk`; o Gradle a instala no primeiro build se as licenças estiverem aceitas: `sdkmanager --licenses`), NDK 28.2.13676358, `rustup target add aarch64-linux-android` e cargo, perl e make (o OpenSSL é compilado junto). Variáveis: `JAVA_HOME`, `ANDROID_HOME`, `NDK_HOME`, `ANDROID_NDK_HOME` e, no `PATH`, o toolchain do NDK (`$NDK_HOME/toolchains/llvm/prebuilt/<sistema>/bin`, onde ficam o `ranlib` e o clang que o OpenSSL usa).

```sh
pnpm --filter @simplemd/desktop tauri android init --ci                              # uma vez; gera apps/desktop/src-tauri/gen/android/ (ignorado pelo git)
pnpm --filter @simplemd/desktop tauri android build --apk --debug --target aarch64
adb install -r apps/desktop/src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
```

Limitações atuais:

- a pasta de notas fica nos dados privados do app (`<dados do app>/vault`); não há seletor de pasta;
- a chave de IA não pode ser guardada (`KEYCHAIN_UNAVAILABLE`);
- exportar e importar pelo seletor do sistema falha (o seletor devolve `content://`);
- a interface ainda é a do desktop, sem ajuste de toque nem da barra de status;
- o APK debug é assinado com a chave de debug; um APK de release exige um keystore (decisão do mantenedor).

### Harness de testes (Chromium)

`pnpm dev:harness` serve a interface do desktop com o `LocalFsProvider` real sobre um vault em memória (nunca entra no build do Tauri). Parâmetros: `?vault=FX-SMALL` (ou `FX-EMPTY`, `FX-2000`, `FX-LP`, `FX-DUP`, `FX-LONG`, `FX-10K`, `FX-1MB`, `FX-CFG-BAD`, `FX-CFG-UNK`, `FX-LATIN1` e, do r7, `FX-R7` — links, wikilinks, imagens, tabelas, HTML e consultas —, `FX-RICH-R7-10K`, `FX-2000-TASKS` e, do r37c, `FX-SEARCH` — busca no texto: acentos, CRLF, BOM, nota de 2 MiB + 1, Latin-1, links, nota só na nuvem, trecho com HTML e nome com U+202E), `&expand=all`, `&persist=1` e `&cloud=a.md,sub/c.md` (deixa essas notas só na nuvem, como um cliente de sincronização que liberou espaço, logo antes de abrir a pasta). O objeto `window.__simplemdHarness` simula mudanças externas (`externalWrite`, `touch`, `remove`), injeta falhas (`fault('write', { error: 'IO' })`; `fault('read', { delayMs })` também deixa a busca no texto lenta), registra as chamadas (`calls()`), troca o resultado do diálogo de pasta (`dialogs.open`), fixa o relógio (`setClock`) e simula o fechamento da janela (`requestWindowClose()`). Do r7: `opener` (pedidos de "abrir URL", sem abrir nada), `lt` (LanguageTool falso: ausente, atraso, erro), `images` (blobs das imagens), `editorViewConstructions()` e os contadores de `renderCounts()` (`blockBuilds`, `sanitizeRuns`, `queryEvals`, `lintRuns`, `ltRequests`…).

Com `&persist=1`, a pasta e a camada global de dicionários vão para o `sessionStorage` ao sair da página, cada uma com teto de 4 Mi caracteres. Acima do teto, ou se o navegador recusa pela cota, a chave sai (nada velho volta na recarga), a carga seguinte avisa no console (`[harness] &persist=1 não guardou`) e `__simplemdHarness.persist.skipped()` devolve o que não foi guardado (`key`, `chars` e `reason`: `cap` ou `quota`).

### Live preview

O live preview mostra o markdown renderizado sem mudar o texto do arquivo. Com o editor focado, o elemento sob o cursor ou a seleção volta a mostrar o markdown cru: o nó (ênfase, link), a linha (título, marcador de lista) ou o bloco (código, tabela, HTML, consulta). Nada disso grava no arquivo: só um gesto seu (clique numa caixa de tarefa, comando, digitação) muda a nota.

No app desktop as notas abrem no **modo fonte**, com o markdown cru (na demo a prévia vem ligada). ⌘E (Ctrl+E no Windows/Linux), o comando "Editor: alternar live preview" da paleta ou o item "Fonte"/"Prévia" à esquerda da barra de status ligam e desligam o live preview da nota mostrada, na hora: a nota não é gravada nem fica modificada, e o cursor, a seleção e o desfazer ficam como estavam. Cada aba guarda o próprio modo durante a sessão, inclusive quando a nota é recarregada do disco. Para as notas abrirem com a prévia: Configurações → **Editor** → "Ao abrir uma nota" → "Prévia ao vivo" (fica em `editor.defaultMode` no `.simplemd/config.json`, `"source"` ou `"live"`); vale para as notas abertas depois, e as abas abertas ficam como estão. Um valor inválido no arquivo vale como "Fonte", com aviso (o select mostra "Fonte (valor inválido no arquivo)"), e o arquivo não é regravado até você escolher um modo, inclusive "Fonte (padrão)". No modo fonte, diagramas Mermaid, fórmulas KaTeX, resultados do calc, consultas, tabelas, imagens e HTML ficam crus (o Mermaid e o KaTeX nem são carregados); ⌘/Ctrl-clique e a dica nos links, ⌥↩, ⌘L nas tarefas e ⌘⇧↩ continuam valendo.

- **Texto:** títulos `#` a `######` sem as marcas e com tamanho por nível, negrito e itálico sem os marcadores, tachado `~~x~~`, código em linha (uma ou mais crases) com fundo próprio, marcadores de lista como `•` (números continuam visíveis), citações `>` com uma barra por nível (até 6, com continuação preguiçosa), blocos de código cercados com fundo próprio e cercas atenuadas, e tabelas GFM de topo como `<table>` com o alinhamento da linha `:---:` (clicar numa célula põe o cursor na célula correspondente da fonte).
- **Links:** em linha `[t](url "título")`, por referência `[t][r]`, `[r][]` e `[r]` (só quando a definição `[r]: url` está na nota; sem definição ficam crus), autolinks `<https://…>`/`<a@b.c>` e URLs soltas (`https://…`, `www.…`) mostram só o texto com o estilo de link; o destino fica no nome acessível e numa dica que aparece depois de 0,5 s com o ponteiro em cima.
- **Tarefas:** `- [ ]`, `* [x]`, `+ [X]`, `1. [ ]`, `[-]` (cancelada) e `[/]` (em andamento) viram caixas de seleção (`role="checkbox"`, `aria-checked` true/false/mixed). Clicar troca só o caractere da caixa (um passo de desfazer); "Alternar tarefa" (⌘L / Ctrl+L) alterna as tarefas da seleção. Com o plugin "Tarefas e consultas" ligado (padrão), concluir acrescenta ` ✅ AAAA-MM-DD` e uma tarefa recorrente (`🔁 every week`) cria a próxima ocorrência — veja [`docs/consultas.md`](docs/consultas.md).
- **Imagens da pasta:** `![alt](caminho "título")`, `![alt](<com espaços>)` e `![alt][ref]`, relativas à nota (`/x.png` = raiz da pasta, `%20` decodificado, `../` só dentro da pasta). Tipos png, jpg/jpeg, gif, webp e svg, com a extensão **e** os bytes conferidos; até 20 MB (raster) e 2 MB (SVG). SVG é mostrado só como imagem (nada do conteúdo executa). Imagens remotas (`https:`), `data:` e `file:` ficam como texto, sem nenhuma requisição. Recusas mostram "Imagem não encontrada: <caminho>", "Imagem fora da pasta", "Tipo de imagem não suportado", "Imagem maior que 20 MB" ou "SVG maior que 2 MB". Imagens fora da pasta, sob `.git`/`.simplemd`, ocultas, atrás de links simbólicos/junções ou com hard link (no macOS/Linux, mesmo que as duas entradas estejam na pasta) aparecem como "Imagem fora da pasta". Uma mudança no arquivo da imagem recarrega sozinha.
- **HTML cru:** veja "HTML cru" em [Exportação](#exportação) — o editor e a exportação usam a mesma política.

### Prévia lado a lado

⌘⇧D (Ctrl+Shift+D no Windows/Linux), o comando "Editor: alternar prévia lado a lado" da paleta ou o botão "Fechar prévia" abrem e fecham, ao lado do editor, a prévia **só leitura** da nota ativa (diferente do live preview do ⌘E, que renderiza dentro do próprio editor). Ela mostra o HTML da exportação — diagramas Mermaid, fórmulas KaTeX, tabelas, resultados do `calc` e consultas como instantâneo — com a mesma política do HTML cru: nada da nota executa ali, imagens remotas aparecem como o texto alternativo e as da pasta vêm da mesma cache do editor. A prévia acompanha a digitação 300 ms depois da última tecla (em notas pesadas espera mais, até 2 s) e segue a aba ativa; ela nunca grava a nota e o editor não é recriado. A rolagem acompanha o último painel em que você rolou, clicou ou digitou. Links da prévia abrem como no editor (nota, título, navegador) e a janela nunca navega. Um bloco que a conferência de segurança recusa aparece como "Bloco não exibido na prévia: conteúdo recusado por segurança." no lugar dele, e o painel diz quantos foram.

O divisor entre os dois funciona pelo teclado (Tab até ele; ←/→ 2 %, Shift+←/→ e PageUp/PageDown 10 %, Home/End nos limites) e pelo ponteiro (arrastar; Esc cancela; duplo clique volta a 50 %). Cada lado tem no mínimo 320 px. Com menos de 900 px para o editor (janela estreita, ou o painel lateral aberto numa tela de 1280 px) a prévia fica indisponível: o comando e a tecla dizem quanto falta, e uma prévia aberta some com um anúncio e volta quando houver espaço. Aberta ou fechada e a proporção do divisor ficam em `layout.preview` (`open` e `ratio`, de 0,1 a 0,9) no `.simplemd/config.json` da pasta, gravado só quando você muda (as outras chaves de `layout` ficam); um campo inválido vale como o padrão dele (fechada; 50 %) sem descartar o outro (um `open` inválido mantém um `ratio` válido), entra no aviso de valores inválidos do `config.json` e o arquivo não é regravado. Sem pasta aberta, a escolha vale só na sessão.

### Editor dividido

⌘\ (Ctrl+\ no Windows/Linux; atalho global) ou "Dividir editor" na paleta abrem um segundo grupo de abas à direita, vazio e com o foco: o foco vai ao explorador ("Editor dividido. Escolha uma nota no explorador para abrir no grupo da direita.") e a nota escolhida abre nele. Cada grupo tem a sua faixa de abas e o seu editor, criado uma vez: trocar de aba num grupo não recria nada, e cada nota grava só no próprio arquivo (autosave e conflito continuam por aba). Uma nota fica num grupo só: abri-la de novo (explorador, link, catálogo) leva o foco ao grupo onde ela está. Clicar ou entrar com o foco num grupo faz dele o grupo com foco — comandos da paleta, ⌘E, tarefas, tabelas, IA, Ctrl+Tab, ⌘W, a barra de status e a prévia lado a lado agem nele; no outro, a aba ativa fica sem a faixa e sem o negrito. Com o editor dividido, cada grupo é um grupo nomeado para o leitor de tela ("Grupo da esquerda"/"Grupo da direita"), e a faixa diz qual é ("Arquivos abertos, grupo da direita").

⌘\ de novo ou "Juntar grupos do editor" juntam tudo no grupo com foco (as abas dele primeiro, a nota com o cursor, o desfazer e o modo de antes; "Editor em um grupo só."). O botão × "Fechar grupo da esquerda/direita" no fim da faixa, ⌘W num grupo vazio e fechar a última aba de um grupo devolvem as abas ao outro. Dividir pede uma nota aberta e 640 px para o editor (com o painel lateral aberto numa tela de 1024 px, a tecla e o comando dizem quanto falta); estreitar a janela depois não junta os grupos. Com a prévia lado a lado aberta, os dois grupos ficam com 640 px no mínimo e a prévia precisa de 960 px no total. A divisão vale só para a sessão da pasta (nada vai para o `config.json`).

### Links, wikilinks e o painel "Links"

- **Abrir um link:** ⌘-clique (macOS) / Ctrl-clique (Windows/Linux) ou "Abrir link sob o cursor" (⌥↩ / Alt+Enter, também na paleta). Clique simples só põe o cursor. `http`, `https` e `mailto` abrem no navegador ou no cliente de e-mail do sistema; a URL é validada no app e de novo no Rust (`HTTPS://` é normalizado). Qualquer outro esquema (`javascript:`, `file:`, `data:`, `ftp:`…), link com usuário e senha (`https://banco.com@mal.com`), com caracteres de controle ou de formatação invisíveis (direção de texto, U+200B, U+FEFF…), com mais de 2.048 caracteres, `mailto:` com parâmetros fora de `to`, `cc`, `bcc`, `subject`, `body` e `in-reply-to` (anexos nunca) e arquivo que não é nota (`relatorio.pdf`) mostram "Link não suportado: …" e nada abre. No máximo 5 aberturas a cada 10 segundos.
- **Links para notas:** um `.md` relativo (`[t](../b.md#titulo)`) abre a nota no app e leva o cursor ao título; fora da pasta → "Link fora da pasta"; nota inexistente → "Nota não encontrada" (nada é criado).
- **Wikilinks:** `[[alvo]]`, `[[alvo|apelido]]`, `[[alvo#Título]]`, `[[alvo#Título|apelido]]`, `[[#Título]]` (título na própria nota), `[[pasta/alvo]]` e `[[alvo.md]]`; numa tabela o apelido usa `\|`. Fora do cursor aparece só o rótulo (apelido > alvo > `alvo › Título`). Não viram wikilink: `` `[[x]]` ``, bloco de código, front matter, `\[[x]]`, `![[x]]` (embutir não é suportado) e alvo com quebra de linha ou mais de 1.000 caracteres. A resolução ignora caixa e `.md` (acentos contam: `Pão` ≠ `Pao`); com nomes repetidos em pastas diferentes vence a da mesma pasta da nota, depois a de menos pastas, depois a primeira em ordem alfabética, e a dica mostra o caminho escolhido e até 3 outras notas com o mesmo nome.
- **Criar nota por wikilink:** um wikilink inexistente aparece atenuado, com sublinhado tracejado; o ⌘/Ctrl-clique **cria** a nota vazia (sem `/` na pasta da nota atual; com `/`, a partir da raiz, criando as pastas) e a abre. O app nunca sobrescreve: se o arquivo aparecer nesse meio-tempo, abre o existente. Nomes recusados (aviso, nada gravado): `\ : * ? " < > |`, caracteres de controle ou invisíveis, `.`/`..` como pasta, começo com ponto (inclui `.simplemd/…`), ponto ou espaço no fim, nomes reservados do Windows (`CON`, `PRN`, `AUX`, `NUL`, `COM1`–`COM9`, `LPT1`–`LPT9`), trecho com mais de 255 bytes e caminho com mais de 1.024 caracteres.
- **Painel "Links"** (painel lateral, entre Propriedades e Chat IA; comando "Mostrar links"): as notas que apontam para a nota ativa (wikilinks e links `.md` relativos), agrupadas por nota, com a contagem e o trecho da linha com o link destacado. Tab até a lista "Ocorrências", ↑/↓/Home/End/PageUp/PageDown, Enter abre a origem na linha. Atualiza sozinho ao salvar (≤ 2 s). Uma nota com mais de 1.000 links indexa só os 1.000 primeiros (com aviso). As abas do painel lateral quebram a linha quando não cabem.
- **Índice entre versões:** o índice (`.simplemd/index.json`) é um cache. Esta versão grava o formato 3 (links, tarefas, propriedades e tags); uma versão anterior do app que abrir a mesma pasta reconstrói o índice no formato dela e vice-versa — dois aparelhos com versões diferentes numa pasta sincronizada pagam uma reconstrução a cada troca, sem perder dados.

### Catálogo e notas só na nuvem

O painel "Catálogo" (painel lateral) lista as notas da pasta. A busca acha título, caminho e tag sem diferenciar acentos nem maiúsculas: `#receita` filtra pela tag exata, venha ela do front matter (`tags:`) ou do corpo da nota (`#receita` no texto, fora de código, links e HTML); um termo sem `#` também acha parte de uma tag. Os chips de cada linha continuam mostrando só as tags do front matter.

**Buscar no texto das notas** (⌘⇧G / Ctrl+Shift+G, ou o comando da paleta com esse nome): o Catálogo passa ao modo **Conteúdo** (grupo "Buscar em": Notas | Conteúdo) com o foco no campo. A busca começa 250 ms depois da última tecla e acha o termo no corpo das notas sem diferenciar acentos nem maiúsculas ("acao" acha "Ação" e "AÇÃO"), literal (sem expressões regulares; espaços contam, então uma frase quebrada em duas linhas não casa), com ao menos 2 caracteres. Os resultados aparecem enquanto chegam, agrupados por nota (título, caminho e quantas vezes o termo aparece), com até 5 trechos por nota; "Buscando… N notas" mostra o progresso e "Cancelar" (ou Esc no campo) para a busca, mantendo o que já veio; Enter no campo refaz na hora a busca cancelada (ou que deu erro), sem editar o termo. Teclado: ↓ do campo vai à lista; ↑/↓, Home/End e PageUp/PageDown andam pelos trechos (subindo, a lista rola até o cabeçalho da nota do trecho, com título e caminho, quando ele cabe na tela junto com o trecho); Enter (ou clique) abre a nota com o trecho selecionado no meio da tela; Esc volta ao campo. Numa aba com edições ainda não salvas, o app procura o termo na mesma linha (sem ele, vai ao início da linha). A busca para em 200 notas ("refine o termo"), não segue links simbólicos, não lê pastas ocultas (`.simplemd`, `.git`), notas acima de 2 MB, fora do UTF-8 nem notas só na nuvem (nunca as baixa, mesmo com a opção abaixo ligada) e diz quantas notas não leu; `node_modules` entra, como no explorador. Nada é gravado nem indexado: o texto só passa pela memória durante a busca. Uma busca por pasta: digitar de novo cancela a anterior, e trocar de pasta cancela e limpa — uma busca presa na pasta anterior (disco de rede travado) é abandonada e nunca segura a próxima. Nomes, caminhos e trechos mostram os controles de direção do Unicode (U+202A–U+202E e U+2066–U+2069) como `%HH` visível (um nome `fatura` + U+202E + `txt.md` aparece como `fatura%E2%80%AEtxt.md`), para que nenhum nome finja outra extensão. Um nome em árabe ou hebraico aparece normal, porque a direção vem das próprias letras e cada nome fica isolado do texto vizinho; só os controles colados a ele (inclusive os isoladores U+2066–U+2069) viram `%HH`.

Configurações → **Pasta** → "Indexar notas só na nuvem" (desligado por padrão; fica em `index.cloudOnly` no `.simplemd/config.json` da pasta). Desligado, uma nota que o OneDrive, o Proton Drive ou outro cliente de sincronização deixou só na nuvem entra no catálogo só pelo nome do arquivo, sem ser baixada. Ligado, o app lê essas notas para indexar título, tags e links, e o sistema as baixa; enquanto isso a seção e o painel Catálogo mostram "Baixando N notas da nuvem para indexar…". Ao ligar, o anúncio só fala em download quando há nota só na nuvem. Sem conexão, as que não baixarem ficam só pelo nome e o download é tentado de novo nas verificações da pasta, cada vez mais espaçadas (pula 1, 2, 4… até 64 verificações; com a verificação por sondagem, de 1 s, isso chega a cerca de uma tentativa por minuto por nota); uma nota que mudou ou foi baixada fora do app, ou desligar e ligar a opção, tenta de novo na hora. Desligar não apaga o que já foi lido. Sem pasta aberta, a opção fica desabilitada. Abrir a nota no editor sempre a baixa. Roteiro da QA real: `docs/qa/nuvem.md`.

### Tabelas

Na paleta, "Tabela: …" reúne 22 comandos para tabelas GFM de topo: Formatar tabela (⌘⇧F / Ctrl+Shift+F), Formatar todas as tabelas, Próxima célula / Célula anterior (⌘⌥→/← / Ctrl+Alt+→/←; com "Tecla Tab no editor" ligada, também Tab/Shift-Tab), Próxima linha (Enter na tabela; Shift-Enter quebra a linha normalmente), inserir, excluir e mover linhas e colunas, alinhar coluna (esquerda, centro, direita, sem alinhamento), ordenar linhas por coluna (crescente/decrescente) e transpor. Formatar alinha as colunas pela largura visual (CJK e emoji = 2 colunas, inclusive emoji com tom de pele, família com ZWJ, keycap e bandeira), mantém os `:` de alinhamento, `\|` e o código entre crases, completa células faltantes e não muda o conteúdo das células; formatar de novo não muda nada, e cada comando é um passo de desfazer. Ordenar trata a coluna como número quando toda célula não vazia é número (ponto ou vírgula decimal: `3,5`, `-1.25`, `2e3`) e senão como texto em pt-BR (acentos junto da letra, `item 2` antes de `item 10`); vazias primeiro no crescente e por último no decrescente, com a ordem do documento mantida entre iguais. Fora de tabela: "Coloque o cursor numa tabela"; tabela dentro de lista ou citação: "Tabelas dentro de listas ou citações não são suportadas". O motor (`@tgrosinger/md-advanced-tables`, MIT) é carregado sob demanda.

### Tecla Tab e teclado

Configurações → **Editor** → "Tecla Tab no editor" (desligada por padrão; fica em `editor.captureTab` no `.simplemd/config.json`). Desligada, Tab e Shift-Tab saem do editor, como antes. Ligada, Tab/Shift-Tab vão, nesta ordem, para a próxima parada de um snippet LaTeX, a próxima célula de tabela, o item de lista (indenta/desindenta o item com os subitens) ou inserem uma indentação; com o popup de sugestões aberto, Tab fecha o popup sem aceitar. Para sair do editor com a tecla ligada: **Ctrl+M** (macOS **⌥⇧M**) alterna entre "Tab indenta" e "Tab move o foco" (anunciado; também na paleta como "Tab: alternar entre indentar e mover o foco"), **Esc e depois Tab** em até 2 s, ou qualquer atalho global (⌘/Ctrl+O, paleta…). O modo vale para todas as abas na sessão e volta a "Tab indenta" ao abrir o app. Toda ação do Tab tem também um atalho sem Tab: `Mod-]`/`Mod-[` indentam/desindentam o item de lista com os subitens e `Mod-Alt-→/←` vão ao próximo/anterior campo (tabela, snippet). A barra de status no fim do editor aparece sempre que há uma nota aberta e, sem nota, quando a tecla Tab, o Vim ou o LanguageTool estão ligados. O primeiro item dela, "Fonte"/"Prévia", é um botão (uma parada de Tab; Enter ou Espaço alterna o live preview); ⌘E (Ctrl+E) faz o mesmo com o foco em qualquer lugar da janela, fora dos diálogos.

O código de um plugin desligado não é baixado. Plugins com opções mostram o botão "Opções" (as opções ficam em `.simplemd/plugins/<id>/data.json` e podem ser editadas com o plugin desligado).

O modo aparece na barra de status, logo depois do item "Fonte"/"Prévia" ("NORMAL", "INSERÇÃO", "VISUAL", "VISUAL LINHA", "VISUAL BLOCO", "SUBSTITUIR"), e o leitor de tela ouve "Modo Vim: <modo>". `:w`, `:q`, `:wq` e `:x` não fazem nada (o salvamento continua automático). Com o editor dividido, a barra mostra o modo do Vim do grupo com foco; logo depois de dividir, com o grupo novo ainda vazio, ela segue mostrando o modo do último editor usado.

Sublinhado pontilhado e ícone na margem; passe o ponteiro ou use ⌘⇧↩ (Ctrl+Shift+Enter) para o cartão com a regra, a descrição e "Saiba mais"; ⌘⇧M (Ctrl+Shift+M) abre o painel "Problemas"; F8/Shift+F8 vão ao próximo/anterior. Regras: o padrão do markdownlint sem MD013, MD033 e MD041, ou o `.markdownlint.jsonc`/`.markdownlint.json` da raiz da pasta (só JSON, até 64 KB; o `.jsonc` vence; `extends` ignorado; YAML/JS nunca são lidos). Nada é apontado dentro de `$…$`, `$$…$$`, blocos `mermaid` e `=calc`.
- **Snippets LaTeX:** dentro de `$…$`/`$$…$$` (nunca em código, front matter ou HTML), gatilhos como `x/` → `\frac{x}{}` ou `@a` → `\alpha` expandem com campos navegáveis (⌘⌥→/←, e Tab com a "Tecla Tab no editor"); Esc encerra. "Expandir snippet LaTeX" (⌘⇧E) na paleta. Snippets próprios em `.simplemd/latex-snippets.json`.
- **Outliner:** comandos "Lista: …" para mover o item com os subitens (⌃⌘↑/↓ no macOS, Ctrl+Shift+↑/↓ nos demais), indentar/desindentar (⌘]/⌘[ · Ctrl+]/Ctrl+[, e Tab/Shift-Tab com a "Tecla Tab no editor"), dobrar/desdobrar item e tudo; Enter, Backspace, Delete, ⌘⌫ (macOS), ←/Ctrl+← e Mod-A (item → lista → documento) como no obsidian-outliner 4.10.2; guias verticais por nível (clicar dobra o item) e arrastar pelo marcador (Esc cancela). A dobra é só visual: não muda o arquivo. Marcador, numeração e indentação do documento são preservados; cada operação é um passo de desfazer.
- **Ortografia offline:** o dicionário pt-BR embutido (VERO) mais o seu dicionário, no próprio app: nada sai do computador. Só a prosa (as mesmas exclusões do LanguageTool) e só o trecho visível e o editado, 400 ms depois de parar de digitar; a palavra que você está escrevendo espera o cursor sair dela. Com o LanguageTool ligado, um erro de ortografia aparece uma vez só. Desligado, o dicionário embutido nem carrega.
- **Ortografia e gramática (LanguageTool):** precisa de um servidor LanguageTool **instalado à parte** neste computador, na porta 8081 (o simpleMD não empacota o LanguageTool). O texto vai só para `127.0.0.1:8081` (ou `[::1]:8081`), pelo Rust; o servidor local não tem autenticação, então qualquer programa que escute nessa porta recebe o texto enquanto o plugin está ligado. Língua pelo `lang` do front matter ou pela opção "Idioma padrão"; modo automático (1 s depois da última edição) ou manual ("Verificar ortografia e gramática agora", ⌘⇧O / Ctrl+Shift+O); o cartão e o painel são os mesmos do lint, com "Trocar por", "Adicionar ao dicionário" e "Desativar regra". O dicionário tem duas camadas: **deste computador** (nos dados do app, vale em todas as pastas; o padrão de "Adicionar palavras ao") e **desta pasta** (`.simplemd/dictionaries/*.txt`, viaja com ela). Em Opções → "Dicionário", mesmo com o plugin desligado, você escolhe a camada, busca e remove palavras (até 100 na tela; remover tira a palavra de todos os `.txt` da camada) e importa uma lista de termos (`.txt` com uma palavra por linha ou `.dic` do Hunspell, até 10 MiB) com "Importar lista de termos…", que depois aparece em "Listas importadas" para renomear ou remover. ### Cores de pasta nas abas

Para diferenciar as abas pela pasta: foque uma pasta no explorador (clique ou setas), abra a paleta (⌘⇧P / Ctrl+Shift+P) e escolha "Pasta: definir cor…"; a mesma caixa passa a listar 8 cores (Vermelho, Laranja, Âmbar, Verde, Azul-petróleo, Azul, Violeta, Rosa; digite para filtrar) e Enter aplica. "Pasta: remover cor" tira a cor própria (fica desabilitado, com o motivo, se a pasta não tem cor própria). As subpastas sem cor própria herdam a da pasta colorida mais próxima; notas na raiz não têm cor. A aba ganha uma faixa no topo (mais grossa na ativa), uma bolinha e o nome da pasta de origem; o explorador mostra a bolinha só na pasta que define a cor. As cores ficam em `.simplemd/config.json` → `folderColors` (`{ "Projetos": "blue" }`, até 500 entradas; ids `red orange amber green teal blue violet pink`). Entradas inválidas são ignoradas com um aviso, sem regravar o arquivo. Se uma pasta colorida for renomeada, movida ou apagada fora do app, ela perde a cor (o app avisa) e a entrada sai na próxima gravação do `config.json`. Os valores são os tokens `--color-folder-<id>` (claro em `tokens.css`, escuro em `simplemd-dark.json`); um tema do usuário pode defini-los, mas não precisa.

### Estilo do explorador

Em "Configurações" → "Aparência", a seção "Explorador" muda como as pastas com cor aparecem no explorador (as abas não mudam): "Estilo" escolhe entre Bolinha (o padrão, como acima), Faixa lateral (borda de 4 px à esquerda da linha), Cartão (fundo tingido + borda) e Cartão com degradê (fundo claro → saturado da esquerda para a direita); "Arco-íris nas pastas do topo" dá às pastas filhas diretas da raiz as 8 cores em sequência, na ordem do explorador (a 9ª volta ao vermelho; pasta com cor própria mantém a sua e ocupa a posição; criar, apagar ou renomear uma pasta do topo pode mudar as cores das seguintes; nada é gravado em `folderColors`); "Intensidade" (Sutil, Média, Forte) e "Onde aplicar" (só pastas com cor, ou também as subpastas num tom mais claro; notas nunca) ficam desabilitados, com o motivo, em Bolinha. Tudo vale na hora; Esc fecha sem desfazer. A escolha vai para `.simplemd/config.json` → `appearance.explorer` (`{"style":"dot|stripe|card|gradient","auto":"off|rainbow","intensity":"subtle|medium|strong","scope":"own|inherit"}`) só quando você muda algo; valor inválido usa o padrão daquele campo com um aviso, sem regravar o arquivo. Os tons vêm dos tokens `--dimension-folder-*` (porcentagens de `color-mix` sobre `--color-folder-<id>`; claro em `tokens.css`, escuro em `simplemd-dark.json`); um tema do usuário pode defini-los, mas não precisa.

### Temas e fontes

A engrenagem "Configurações" (ou `Mod-,`) abre o diálogo com o tema ("Sistema", "simpleMD Claro" ou "simpleMD Escuro"), a família da fonte do editor (JetBrains Mono, Fira Code, Cascadia Code ou a monoespaçada do sistema), o tamanho (10–32 px) e as ligaduras. Tudo vale na hora, sem recarregar. "Sistema" (`"theme": "system"`) segue o claro/escuro do sistema operacional: usa "simpleMD Escuro" com o SO no modo escuro e "simpleMD Claro" no claro, e acompanha a troca do SO ao vivo; sem escolha gravada, o padrão continua "simpleMD Claro". Com uma pasta aberta, as escolhas vão para `<pasta>/.simplemd/config.json` (outras chaves do arquivo são preservadas) e voltam ao reabrir a pasta; se o arquivo estiver malformado, o app usa os padrões e não o regrava, e um tema salvo que não existe vale como "simpleMD Claro", com aviso. A barra de título da janela segue o SO, não o tema escolhido. Os temas usam os tokens de `packages/themes/src/tokens.css` (nomes `--<grupo>-<nome>`, ver `PLANO.md` §4.2); as fontes embutidas e suas licenças OFL ficam em `packages/themes/src/fonts/`.

### Editor de temas

Em "Configurações", "Editor de temas…" abre um formulário com as 8 cores, as duas fontes e o tamanho do tema, mais nome e base (claro/escuro), e uma prévia ao vivo que só muda dentro do próprio editor. "Salvar como novo tema" grava `<pasta>/.simplemd/themes/<slug>/theme.json` (nunca substitui um tema existente: `<slug>-2`, `<slug>-3`…) e ativa o tema na hora. "Exportar tema…" grava o tema selecionado num arquivo à sua escolha; "Importar tema…" valida um `theme.json` (até 256 KB) e o copia para a pasta sem ativá-lo. No harness, a exportação vira um download e a importação usa o campo de arquivo `set-import-input` (exemplos em `apps/desktop/harness/fixtures/themes/`).

### Exportação

O menu "Exportar" da barra (e a paleta; `Mod-P` = PDF) exporta a nota ativa como ela está no editor, mesmo antes de salvar. "Exportar como Markdown…" grava os mesmos bytes que salvar gravaria (com a opção "Sem front matter"); "Exportar como HTML…" gera um único arquivo com estilo claro embutido, diagramas Mermaid em SVG, fórmulas KaTeX (fontes embutidas só quando há fórmula) e resultados do `calc`, sem scripts; HTML cru da nota sai renderizado pela mesma política de segurança do editor (veja "HTML cru" abaixo). "Exportar como PDF…" abre o painel de impressão do sistema com só o documento, em A4, sempre claro ("Salvar como PDF" no macOS). O destino é escolhido no diálogo do sistema e o próprio arquivo da nota é recusado. No harness, `dialogs.save` aceita `same-as-source`/`denied`, `exportText(i)` devolve o arquivo gerado, `print.mode = 'hold'` segura a impressão até `print.release()` e `exportHtml(md)` devolve o HTML de produção.

HTML cru (I-10): blocos HTML de topo (`<details>`/`<summary>`, tabelas, `<div>`…; dentro de citação ou lista o bloco fica cru, no editor e na exportação) e tags em linha balanceadas no mesmo parágrafo, só de conteúdo de frase (`<kbd>`, `<mark>`, `<br>`, `<sub>`/`<sup>`, `<b>`, `<a>`…), aparecem renderizados no editor fora do cursor e na exportação; com o cursor dentro, com tag sem fechamento, com um elemento de bloco no meio do parágrafo (`x <div>…</div> y`) ou com uma tag em linha da qual nada sobra, o cru volta. Tudo passa por uma política única (DOMPurify): sem scripts, manipuladores `on*`, formulários, mídia, `iframe`/`object`/`embed`, SVG/MathML, `class`/`id`/`name`; `style` só com cor, fundo, alinhamento, peso, itálico e decoração do texto (sem espessura); links só `http`/`https`/`mailto` ou relativos (no editor, ⌘/Ctrl-clique abre, clique simples põe o cursor na fonte e a dica mostra o destino real; na exportação, um relativo que sai da pasta vira só o texto); `<img>` só do vault (remota vira o texto alternativo). Um bloco em que nada sobra mostra "HTML sem conteúdo exibível (removido por segurança)."; `<details>` abre e fecha só na vista (o arquivo não muda), e "Interagir com o elemento sob o cursor" (⌘⇧↩ / Ctrl+Shift+Enter) leva o foco ao resumo e aos links do bloco.

Imagens, wikilinks e consultas (r7): o HTML exportado embute as imagens da pasta como `data:` (tipo conferido pelos bytes; SVG só em `<img>`), até 50 MB no total — acima disso as restantes saem como o texto alternativo e um aviso explica; o PDF mostra as mesmas imagens; imagens remotas continuam como no arquivo (HTML) ou como o texto alternativo (PDF). Wikilinks saem como texto estilizado (sem link nem colchetes; inexistentes com estilo próprio). Um bloco ` ```tasks `/` ```dataview ` sai como um instantâneo do resultado no momento da exportação quando o plugin "Tarefas e consultas" está ligado (desligado, sai como código).

Limitação conhecida (NB-R1): na exportação HTML/PDF, um diagrama Mermaid cujo SVG usa `foreignObject` (por exemplo `journey`) sai como o código do diagrama, não como desenho: a verificação da saída dos renderizadores recusa `foreignObject` por segurança. No editor o diagrama continua desenhado.

### IA

Configurações → **IA** escolhe o provedor — Ollama (local, roda no seu computador), OpenAI ou Anthropic (na nuvem) —, o modelo e as chaves; as chaves ficam só no keychain do sistema, nunca no `.simplemd/config.json`. O painel "Chat IA" e os comandos "IA: Reescrever seleção", "IA: Resumir seleção", "IA: Traduzir seleção" e "IA: Continuar texto" mandam ao provedor só o que você digita ou seleciona, e só quando você envia ou roda o comando.

- **Autorização por pasta:** antes do primeiro envio de texto de uma pasta para a OpenAI ou a Anthropic, o app pergunta "Enviar para {Provedor}?" e mostra o texto inteiro que vai sair (no chat, também quantas mensagens anteriores vão junto); nada sai antes de você escolher. "Cancelar" (o foco começa nele; Esc também cancela) não envia nada e devolve a mensagem ao campo do chat. "Enviar" envia e grava `"consent": { "<provedor>": true }` na seção `ai` do `.simplemd/config.json` daquela pasta, e ela não pergunta de novo. Vale também quando o provedor de nuvem veio do `config.json` de uma pasta copiada ou sincronizada: sem o registro, o app pergunta antes do primeiro pedido. Uma pasta que já traz o registro não pergunta. O Ollama nunca pergunta.
- **O que o diálogo não mostra:** cada comando de IA vai também com uma instrução fixa do app (o prompt de sistema: "reescreva", "resuma", "traduza para {idioma}" ou "continue"), que não aparece no diálogo; ela é texto do app, igual para todas as pastas, e nunca leva conteúdo da nota. O chat não manda instrução de sistema. No histórico do diálogo, o título de cada resposta ("IA (provedor · modelo)") traz o nome do modelo como está no `.simplemd/config.json` da pasta: numa pasta copiada ou sincronizada, esse nome é declarado por ela e é só texto.
- **Revogar:** Configurações → IA → "Envio para a nuvem nesta pasta" mostra, para cada provedor de nuvem, se a pasta está autorizada; "Revogar" apaga o registro, e o próximo envio pergunta de novo.
- **Histórico do chat:** cada mensagem vai com a conversa da sessão, até 96.000 caracteres no total (a mensagem nova incluída; a conversa fica só na memória da sessão). Acima disso, as mensagens mais antigas ficam de fora, e a sua mensagem mostra o aviso "Mensagens antigas não foram enviadas."
- **Resposta cortada:** quando o provedor para pelo limite do modelo, o cartão de resultado e o chat mostram o aviso "Resposta cortada pelo limite do modelo."

### Demo do editor

`pnpm dev:demo` abre a demo em <http://localhost:5173>. Atalhos: `Mod-B` alterna negrito (`**…**`), `Mod-I` alterna itálico (`*…*`) e `Mod-K` insere um link (`[texto](url)`, com `url` selecionado). `Mod` é Cmd no macOS e Ctrl no Windows/Linux. Parâmetros de URL:

- `?doc=fixture` abre o documento de exemplo do live preview (`packages/core/test/fixtures/live-preview.md`);
- `?doc=large` gera um documento de 10.000 linhas para medir desempenho;
- `&theme=simplemd-dark` abre a demo no tema escuro (o seletor "Tema" troca na hora).

O CI (`.github/workflows/ci.yml`) roda lint, typecheck e `check:security` no Ubuntu, os testes no Ubuntu, Windows e macOS (os testes do vault usam pastas temporárias reais em cada sistema), compila o app Tauri no macOS e no Windows e, no job `export-pdf-windows`, imprime o HTML exportado de `export-fixture.md` em PDF A4 pelo Edge (o motor do WebView2), confere o texto do PDF e guarda o PDF com o sha256 como artefato. Os jobs `secrets` (gitleaks e trufflehog `--only-verified` no histórico inteiro; falsos positivos revisados em `.gitleaksignore`), `audit` (`pnpm audit --prod --audit-level high`, `cargo audit` e osv-scanner nos dois lockfiles; exceções em `apps/desktop/src-tauri/.cargo/audit.toml` e `osv-scanner.toml`) e `semgrep` (regras de `semgrep/semgrep-rules` fixadas num commit, com o sha256 do tarball conferido e a lista em `.github/semgrep-rules.txt`; exceções só com `nosemgrep` justificado na linha) reprovam qualquer achado. As regras ao vivo do registro do Semgrep rodam toda semana no workflow `semgrep-latest.yml`, que não é obrigatório. Toda ação é fixada pelo SHA do commit (o repositório também exige isso e só permite as ações usadas), nenhum checkout guarda a credencial do git e o `check:security` confere essas regras (`scripts/check-ci-supply-chain.mjs`).

Cada perna do `desktop-build` publica como artefato (30 dias) o binário, `dist-digest.txt` e `SHA256SUMS`, para conferir a proveniência com `shasum -a 256 -c SHA256SUMS`; no Windows ela também roda o teste do keychain real (`roundtrip_real_keychain`, com `--include-ignored`), que fica `ignored` no macOS. O workflow `perf.yml` roda a suíte inteira com `SIMPLEMD_PERF=1`, incluindo as asserções de tempo que os jobs `test` pulam; ele não é obrigatório.

A `main` só recebe mudanças por PR, com as 10 verificações obrigatórias verdes (`lint`, `test` nos três sistemas, `desktop-build` no macOS e no Windows, `export-pdf-windows`, `secrets`, `audit` e `semgrep`), o branch atualizado e histórico linear. Só o admin cria tags `v*`, e elas não mudam depois. O `release.yml` roda numa tag `v*` ou à mão; todo `tauri build` (também o do `desktop-build`) roda com `-- --locked`, então o cargo usa o `Cargo.lock` do repositório. À mão, é um dry-run que gera os pacotes sem assinatura de desenvolvedor (dmg, msi e nsis; o `.app` do macOS com assinatura ad-hoc, conferida por `codesign` antes do upload) como artefatos de 7 dias, sem segredos e sem Environment. O pré-lançamento sem assinatura sai do mesmo dry-run, disparado **na tag** com o input `unsigned_prerelease` (`gh workflow run release.yml --ref vX.Y.Z -f unsigned_prerelease=true`): antes do install, o passo `unsigned-prerelease-guard` exige que a ref seja uma tag `v*` de um commit da `main` com a versão do app; depois das duas pernas, o job `publish-unsigned` (Environment `release`, revisor obrigatório, sem checkout) confere a lista exata dos artefatos e publica só o `.dmg` e o `-setup.exe`, com `SHA256SUMS`, atestado de proveniência e as notas geradas no job, num release em **rascunho** marcado como pré-lançamento; o dono publica à mão. No push da tag roda o caminho assinado, no Environment `release` (revisor obrigatório), que exige os segredos de assinatura (hoje o Environment não tem nenhum, e a perna Windows falha até a assinatura do Windows existir); o build roda sem segredos, só o passo `tauri bundle` assina, e o resultado é um release em **rascunho** com `SHA256SUMS` e atestado de proveniência.

### PRs do Dependabot

O Dependabot abre toda semana um PR por grupo (npm, cargo e GitHub Actions; `.github/dependabot.yml`). No do npm, confira antes que o PR só mexe em arquivos `package.json` e no `pnpm-lock.yaml` (o `deps:fix` roda o código do branch) e rode `pnpm deps:fix` no branch do PR, sempre via `pnpm` (é dele o pnpm usado, sem shell; `node scripts/deps-fix.mjs` direto sai com 2): ele faz o que é mecânico e nunca commita nem envia.

1. `pnpm install --frozen-lockfile` (o pnpm reaplica `minimumReleaseAge` e `trustPolicy` ao lock; uma recusa vira pendência, nunca exceção nova).
2. Alinha os overrides de "mesma versão do app" (hoje `mermaid>katex` e `micromark-extension-math>katex`) à versão que o app usa direto e re-resolve o lock (`pnpm install --no-frozen-lockfile`, depois `--frozen-lockfile`); recusa versões diretas diferentes e rebaixamento. Os overrides de segurança (`re2js`, `lodash`, `minimatch`) só mudam por decisão registrada.
3. Escreve no `rules.ts` a versão do markdownlint instalado (URLs "Saiba mais").
4. Acrescenta no `THIRD-PARTY-NOTICES.md` as linhas que o `check-licenses` sugere para dependências de produção com licença permitida; licença proibida ou desconhecida continua reprovando.
5. Regenera `plugins-examples/calc/main.js`.
6. Confere cópia única, versões citadas na seção do r7 do NOTICES, `check-licenses`, ESLint, prettier, typecheck, Vitest, `pnpm audit --prod` e o osv-scanner (se instalado), e imprime o que mudou e o que continua pendente.

Saída 0 = nada pendente; 1 = há pendências (aviso de segurança, teste reprovando, licença, recusa); 2 = erro de uso, de ambiente ou inesperado (uma linha; a pilha com `pnpm deps:fix --verbose`). Revise o `git diff`, commite no branch do PR e resolva as pendências; o merge segue as 10 verificações obrigatórias.
